# Collab Clients

External host adapters for one DSH Collab Runtime. No task database or model executor is bundled.

From the extracted Clients package, run `node setup.mjs install codex` or `node setup.mjs install claude` to preview the exact installation steps. Add `--apply` to use the host CLI, or `--cli /absolute/path/to/executable` if it is not on PATH. Setup refuses a marketplace source conflict, preserves permission settings and never restarts the backend. `node setup.mjs doctor` checks offline discovery; `node setup.mjs doctor --live` additionally verifies authentication and the runtime contract without a model call. DSH-side installation and initial discovery configuration remain managed by the DSH host, as described in the bundled guide.

Download the prebuilt Clients TGZ from the project's Release assets and extract it to a permanent folder. No build or compilation is required. The archive contains self-contained `hosts/codex` and `hosts/claude` directories and local marketplace catalogs. The bundled `GUIDE.zh-CN.md` explains installation and removal. The runtime must advertise `localControlApi: 2`; old clients remain compatible with the runtime's legacy endpoints.

Windows requires Node.js >=22.19 on PATH, or `DSH_MCP_NODE` pointing to Node. The bundled GUI-subsystem launcher suppresses console windows. `DSH_DESKTOP_RUNTIME_FILE` optionally selects the exact local discovery record. Never publish that file: it contains a per-generation local credential.

Codex: register the extracted package with `codex plugin marketplace add <extracted-package>`, then install `dsh-codex-collab@dsh-collab-clients`. Claude Code: use `/plugin marketplace add <extracted-package>` and `/plugin install dsh-collab@dsh-collab-clients`. This does not configure model credentials or run a paid prompt. Inspect the host's MCP connections, then call `deepseek_runtime_status`. Validation and actual model-driven acceptance are reported separately.

The Windows package retains its no-console launcher. The separate `clients-posix` package for macOS/Linux uses `node` on the host's PATH directly; it contains no Windows launcher and does not use `DSH_MCP_NODE`. Add the extracted POSIX package directory as the local marketplace instead of the Windows GitHub catalog. Do not register both packages under the same marketplace name. Ubuntu WSL local installation/connection checks passed on the prior candidate; native macOS and target desktop acceptance remain separate gates.

Default connection records: Windows `%APPDATA%/DeepSeek Harness/runtime.json`; macOS `~/Library/Application Support/DeepSeek Harness/runtime.json`; Linux `${XDG_CONFIG_HOME:-$HOME/.config}/DeepSeek Harness/runtime.json`. Configure DSH's `runtimeFile` to the expanded absolute path. An explicit `DSH_DESKTOP_RUNTIME_FILE` takes precedence and never falls back to another instance if invalid. DSH and the client must run in the same OS/network environment.

MCP progress notifications forward bounded DSH snapshots. The client does not claim experimental MCP task/channel support or wake closed chats. Cancelling a call or closing the host releases its observer while accepted DSH work continues.

Candidate connection diagnostics: from the extracted Clients package (or either `hosts/codex` / `hosts/claude` directory), run `node lib/diagnostics.mjs`. It reads only the normal discovery candidates and prints a report without paths, endpoints, credentials or session content. It distinguishes missing, malformed, unreadable and incompatible records. Multiple valid records now block automatic selection: set `DSH_DESKTOP_RUNTIME_FILE` to the intended host. It never starts DSH, calls the model or proves live connectivity. Exit code 1 means selection/configuration needs attention; after correction, verify with the registered runtime status tool.

The next Runtime/Clients candidate adds `deepseek_task_preflight` (30 tools in the default full profile; the published rc.2 has 27). It previews a new task policy through the existing connection, before any session creation. The calculation uses no native API or model calls. It does not validate an existing session's inherited policy, remaining budget, third-party registration or provider availability. Only actual execution admission grants capabilities. Older Runtime versions do not implement this new tool; update matching packages together in a controlled window.

`DSH_COLLAB_TOOL_PROFILE=core` is an optional 15-tool subset for hosts that need a smaller tool list. The default remains `full`: core omits preflight, advanced schedules, notification and policy operations. Workflows that require those operations must use full. Description compaction retains all budget and permission fields.

Candidate Clients default task receipts to `response_detail: "compact"`. They retain answers, distinct partial output, failures, warnings, IDs, effective permissions and usage totals. Per-request ledger IDs and activity/tool lists are replaced with counts and read-only retrieval instructions; `receiptView.refs` denotes exact equality with another field, not a permission grant. Both MCP text and structured content carry the compact receipt, so text-only hosts retain the same essential data. `response_detail: "full"` retrieves raw detail. DSH task records, UI history, budgets and fees are unchanged.

Prefer the advertised `task_session_id` alias when a host reserves `session_id`. Either works; supplying conflicting values fails before any Runtime request. The alias also supports Direct continuation and nested batch items. `lead_id` remains unchanged. Host-only options are removed before canonical Runtime validation and idempotency checks.

Repeated status/result reads may pass the returned `responseRevision` as `if_response_revision`. A matching visible receipt yields `unchanged: true`; reuse the previous answer instead of treating this as empty output. The Runtime is still read on every call. Conditional reads cannot submit tasks and cannot be combined with full detail. Prefer `deepseek_tasks_wait` for completion polling and paged `deepseek_task_result` for answers; never resubmit a task to fetch its results. Compact progress notifications carry stage/step/sequence and counters rather than repeatedly sending growing partial text; final results and trace remain readable.

`deepseek_task_tree` returns a readable indented task hierarchy in MCP text, plus unchanged IDs, edges, receipts and provenance in `structuredContent`. Both host adapters use this presentation. It does not register DSH tasks as native Codex or Claude subagents, or install a native host chart UI. The collapsible visual tree and policy/schedule panels live in the DSH collaboration center. Client loading, MCP text, DSH browser UI, and paid model-driven research are separate acceptance levels.

Delivery evidence and recovery preview are read-only full-profile tools: `deepseek_task_evidence` and `deepseek_recovery_preview`. They do not verify mathematical correctness or launch recovery automatically. Use matching rc.4 Runtime/Clients.
